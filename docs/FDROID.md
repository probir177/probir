# F-Droid সংযোগ: কীভাবে কাজ করে ও রোডম্যাপ

F-Droid হলো ফ্রি ও ওপেন-সোর্স অ্যান্ড্রয়েড অ্যাপের রিপোজিটরি, এখন প্রায় ৫,০০০ অ্যাপ। এআই অ্যাসিস্ট্যান্ট সরাসরি F-Droid-এর অফিসিয়াল ইনডেক্সের সাথে যুক্ত। ফলে দোকানের কাজ আর প্রোগ্রামিং দুই ক্ষেত্রেই এআই F-Droid ব্যবহার করতে পারে।

## কীভাবে কাজ করে

```
f-droid.org/repo/entry.json ──(প্রতি ৬ ঘণ্টায় যাচাই)──┐
f-droid.org/repo/index-v2.json (~70MB) ──SHA-256 মিলিয়ে─┴─► data/fdroid-cache.json (~19MB)
                                                                     │
                       এআই টুলসমূহ ◄──────────────────────────────────┘
   fdroid_search · fdroid_latest_apps · fdroid_categories · fdroid_app_details
   fdroid_build_recipe ──► gitlab.com/fdroid/fdroiddata (বিল্ড রেসিপি)
   fdroid_source_code  ──► অ্যাপের নিজস্ব GitHub / GitLab / Codeberg রিপো
   fdroid_download_apk ──► APK ডাউনলোড → SHA-256 যাচাই → দোকানের FTP
```

- **প্রথমবার চালু করা:** সার্ভার চালুর সাথে সাথে পেছনে ইনডেক্স ডাউনলোড শুরু হয়। ইন্টারনেটের গতি অনুযায়ী কয়েক মিনিট লাগে, এবং এই সময়ে প্রায় ৩০০MB RAM দরকার হয়। এরপর থেকে ডিস্কের ক্যাশ ব্যবহার হয় এবং খোঁজার ফল মিলিসেকেন্ডে আসে।
- **হালনাগাদ:** প্রতি ৬ ঘণ্টায় শুধু ছোট `entry.json` ফাইলটি দেখে। F-Droid নতুন ইনডেক্স প্রকাশ করলে তবেই পুরোটা আবার নামায়। ইন্টারনেট না থাকলে পুরোনো ক্যাশ দিয়েই কাজ চলে।
- **নিরাপত্তা:**
  - ইনডেক্স আর প্রতিটি APK-এর SHA-256 মিলিয়ে দেখা হয়। না মিললে ফাইলটি বাতিল হয়।
  - সোর্স কোড শুধু F-Droid-এ নথিভুক্ত রিপোজিটরি থেকে পড়া হয়। এআই যেকোনো ওয়েবসাইটে যেতে পারে না।
  - APK ডাউনলোড FTP-তে ফাইল লেখে, তাই "সম্পূর্ণ অটোমেশন" বন্ধ থাকলে আগে অনুমতি চায়।

## রোডম্যাপ

### ধাপ ১: সংযোগ ✅ (সম্পন্ন)
- [x] F-Droid ইনডেক্স ডাউনলোড, SHA-256 যাচাই, ক্যাশ ও স্বয়ংক্রিয় হালনাগাদ
- [x] অ্যাপ খোঁজা, ক্যাটাগরি, সাম্প্রতিক অ্যাপ, পূর্ণ বিবরণ (পারমিশন, SDK, anti-features)
- [x] বিল্ড রেসিপি (fdroiddata) ও সোর্স কোড ব্রাউজিং (GitHub/GitLab/Codeberg)
- [x] যাচাই করা APK সরাসরি দোকানের FTP-তে রাখা

### ধাপ ২: দোকানের অ্যাপ লাইব্রেরি ও স্বয়ংক্রিয় আপডেট
- [ ] FTP-তে রাখা APK-গুলো F-Droid ইনডেক্সের সাথে মিলিয়ে দেখা: কোনটার নতুন ভার্সন এসেছে
- [ ] নির্দিষ্ট সময় পরপর (যেমন প্রতি রাতে) পুরোনো APK নিজে থেকে হালনাগাদ করা, পুরোনো ভার্সন `/apps/_old`-এ সরিয়ে রাখা
- [ ] FTP-তে `catalog.json` / `catalog.html` স্বয়ংক্রিয়ভাবে বানানো: গ্রাহকরা যাতে তালিকা দেখতে পারেন

### ধাপ ৩: দোকানের নিজস্ব F-Droid রিপোজিটরি
- [ ] সার্ভারে `fdroidserver` বসানো (`fdroid init`, সাইনিং কী তৈরি)
- [ ] FTP-র `/repo` ফোল্ডার থেকে স্বাক্ষরিত ইনডেক্স তৈরি করা (`fdroid update`)
- [ ] গ্রাহকরা নিজের ফোনের F-Droid অ্যাপে দোকানের রিপো যোগ করবেন (QR কোড দিয়ে), আর দোকানের সব অ্যাপ ও আপডেট সরাসরি পাবেন
- দরকার: FTP ফোল্ডারটি HTTPS-এ ওয়েবে খোলা রাখা, Python 3 ও fdroidserver

### ধাপ ৪: ডেভেলপমেন্ট ও বিল্ড
- [ ] Android SDK + Gradle থাকা একটি বিল্ড মেশিন বা কন্টেইনার যোগ করা
- [ ] এআই ওপেন-সোর্স অ্যাপ সোর্স থেকে বিল্ড করবে (`fdroid build`), প্রয়োজনে দোকানের নাম বা লোগো দিয়ে কাস্টমাইজ করবে (লাইসেন্স মেনে)
- [ ] দোকানের নিজস্ব অ্যাপ বানিয়ে ধাপ ৩-এর রিপোতে প্রকাশ করা

### ধাপ ৫: গ্রাহক-সেবা
- [ ] গ্রাহকদের জন্য আলাদা পাবলিক পেজ, যেখানে শুধু পড়া যাবে: অ্যাপ খোঁজা, QR কোড দিয়ে ডাউনলোড
- [ ] বাংলায় অ্যাপের সারাংশ (এআই অনুবাদ করে দেবে)

## সেটিংস (`.env`)

| ভেরিয়েবল | ডিফল্ট | কাজ |
|---|---|---|
| `FDROID_ENABLED` | `true` | `false` দিলে F-Droid সংযোগ বন্ধ |
| `FDROID_REFRESH_HOURS` | `6` | কত ঘণ্টা পরপর হালনাগাদ যাচাই হবে |
| `FDROID_MAX_APK_MB` | `300` | সর্বোচ্চ APK সাইজ |
| `FDROID_REPO` | `https://f-droid.org/repo` | অন্য মিরর বা রিপো (index-v2 ফরম্যাট) |
| `DATA_DIR` | `data` | ক্যাশ ফোল্ডার |
| `GITHUB_TOKEN` | — | ঐচ্ছিক। ছাড়া GitHub-এ ঘণ্টায় ৬০ বার কোড দেখা যায় |

## সীমাবদ্ধতা

- প্রতি অ্যাপের সর্বশেষ ৫টি ভার্সনই ক্যাশে রাখা হয়।
- সোর্স কোড শুধু ডিফল্ট ব্রাঞ্চ থেকে পড়া হয়। GitHub/GitLab.com/Codeberg ছাড়া অন্য জায়গায় রাখা কোড সরাসরি দেখা যায় না, শুধু লিংক দেখায়।
- এআই নিজে অ্যাপ বিল্ড করতে পারে না, এটা ধাপ ৪-এর কাজ।
